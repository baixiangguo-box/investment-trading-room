# 架构与数据边界

项目采用 ES modules、Electron 和 Node.js 内置 SQLite。界面不依赖前端框架；价格和成交量图以 SVG 渲染。没有账户服务器、券商接口或上传账本服务。

```text
renderer/               行情、自选、详情、交易、账户和图表
    │ window.trading（受限 API）
desktop/preload.cjs     contextBridge，IPC 白名单
    │ trading:*（校验调用窗口与主框架）
desktop/main.mjs        协调账户、行情、文件对话框、生命周期
    ├── core/           SQLite、交易规则、模拟撮合、完整备份
    └── services/       公开行情请求、解析、缓存、完整目录校验
```

## 目录

| 目录/文件 | 职责 |
|---|---|
| `core/account-service.mjs` | 整数分账本、委托与成交、FIFO/T+1、资金流水、版本与世代、快照和诊断 |
| `core/market-rules.mjs` | 证券板块、数量和价格边界、模拟费率、上海时区交易日历 |
| `services/market-service.mjs` | 行情源请求、响应解析、全目录分页校验、失败退避和缓存 |
| `desktop/main.mjs` | 应用启动、受限协议与 IPC、原生文件对话框、撮合调度和安全关闭 |
| `desktop/platform.mjs` | 保持 Windows 旧数据位置、Mac Application Support、原生 Mac 菜单和快捷键 |
| `desktop/preload.cjs` | 向 renderer 暴露最小 API，保留业务错误码 |
| `renderer/app.js` | 页面、表单、输入状态、恢复预览和异步请求令牌 |
| `renderer/helpers.js` | 数据格式化、API 拆包、图表模型和账户响应版本保护 |
| `renderer/rendering.js` | DOM 更新时保留编辑中的输入节点、光标和选区 |
| `renderer/polling.js` | 前台、后台、休市及失败状态的串行轮询 |
| `tests/`、`scripts/*-qa.mjs` | 隔离的纯逻辑、服务和实际 Electron 回归 |

## 账户一致性

SQLite 使用 WAL、FULL 同步和事务；完整账户以 JSON 保存于 `account_state`，调整前的完整快照保存在 `account_backups`。本金、现金、成交金额、费用及成本以整数分计算。持仓按买入批次保存，支持 FIFO 成本和交易日 T+1 可卖数量。

每个账户带 `version` 与 `generation`。资金调整、重置和恢复强制检查预期版本及世代；自选、委托和撤单要求世代，提供预期版本时也会检查。重置和恢复生成新世代，旧世代的在途操作不能污染新账本。委托编号与完整交易意图绑定；同编号同意图查询或重试不会重复成交，同编号不同意图会被拒绝。冻结现金/数量、部分成交、撤单和资金流水在事务内自洽。

充值和提取仅改变现金并追加资金流水，不算交易盈利。目标总资产调整必须有有效、完整的持仓估值；直接增减虚拟现金可离线使用。主进程先返回已提交的本地账本，行情估值另行刷新；renderer 拒绝较旧账户响应。

快照包含格式版本、完整账本和校验值，恢复时会严格检查字段、资金重放、冻结量、订单及成交一致性。原生导入限 20 MiB，保存先写临时文件再原子重命名。主进程保存十分钟有效的预览令牌，绑定快照及预览时账户版本/世代，renderer 不能指定导入路径或用新版本参数跳过冲突。恢复之前同事务备份当前账户。

自动备份与账本共处一个数据库，历史备份不自动删除。账户 JSON 达到 16 MiB 时拒绝继续扩张并提示导出；不静默删除终态委托或成交记录。重要账户应另行导出外部备份。

## 行情与时间

新浪股票目录按上游总数分页读取，并复查总数、证券唯一性及沪深京覆盖。未完整加载时显示进度；失败、截断或重复目录不替换已完整缓存。股票列表的获取时间不冒充成交日期。

腾讯报价保留真实报价时间、价格上下限及五档量；每项证券独立校验新鲜度、交易日期和盘口可用性。指数和板块永远不可交易。东方财富板块不可用时使用新浪行业概况；两者 ID 和分类分别保留，新浪平均股价不冒充指数点位，缺历史曲线明确提示。

请求最多三路并发，相邻请求起始至少间隔 150 ms，单次超时 10 秒、最多两次尝试，响应体上限 5 MiB。目录、报价、板块和历史有各自缓存与失败退避；手动刷新不绕过失败退避。缓存原有时间与来源不因重试失败被改写。

图表保留上游 OHLC 和实际成交量；分时量从相邻累计量求差，无可核验差量时保留缺失。价格与量柱共用定位模型，缺失均价、量和五档字段明确标示。

交易日历采用上海时区，当前仅核验 2026 年。未知年份关闭模拟成交。报价的成功获取、界面连接状态与可成交状态分别判断；休市能看行情，不等于允许下单成交。

## 桌面边界

renderer 通过本地 `trading://app/` 协议加载白名单文件，CSP 禁止远程脚本及 renderer 网络请求。窗口启用 `contextIsolation`、`sandbox` 和 `webSecurity`，禁用 `nodeIntegration`，拒绝导航、新窗口及权限请求。IPC 校验发送者窗口、主框架与协议来源。

文件读取和网络位于主进程；错误在界面使用友好说明，详细日志留在本地数据目录。账户文件与应用目录分离，账户数据不进入 `app.asar`；包核验脚本检查私有数据缺席以及源文件一致性。默认目录解析 Windows 重定向或 Mac 符号链接的物理路径，以保持缓存原子保存位于同一卷。

Windows 关闭最后一个窗口退出。Mac 关闭窗口仅取消该窗口的恢复预览并保留同一个账户/行情服务，通过 Dock activate、菜单或第二实例事件重开；不重复注册 IPC 和撮合定时器。退出先禁止新 IPC，关闭本应用窗口以结束文件对话框，等待已授权操作与撮合完成，再关闭 SQLite。重复退出不会跳过等待，后台旧窗口的 IPC 不能冒用新窗口授权。

Mac `.app/Contents/Resources/app.asar` 与 Windows `resources/app.asar` 使用相同源码；Mac 额外检查 bundle ID、版本、最低系统、图标及 Mach-O CPU。Electron 下载根目录的许可在 Mac 打包时会被上游清理，因此通过 `mac.extraFiles` 单独保存在 bundle 的 Resources 中。

## 模拟边界

采用公开有效对手报价及有限盘口数量，而非交易所订单队列。费用是统一模拟参数。当前不覆盖完整集合竞价、市价单、盘后交易、公司行为、券商开户、融资融券或证券资金交收；缺行情时不伪装完整资产及收益。改变这些行为须同步更新契约、文档和回归测试。
